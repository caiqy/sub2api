## Context

当前默认值偏向大规格高并发环境，例如上游非流式响应读取默认 128MiB、SSE 单行上限 500MiB、usage worker 池默认并发较高。小内存部署需要通过部署侧配置降低峰值风险。用户已在 Nginx 配置 80m 请求体上限，本 change 将该经验沉淀为项目文档和可复用示例。

## Goals / Non-Goals

**Goals:**
- 给出低内存部署的推荐配置组合和每项配置的效果/副作用。
- 提供上线验证清单，确保配置真实生效。
- 文档指向已有知识库和部署流程，方便后续服务器更新时复用。

**Non-Goals:**
- 不改代码默认值。
- 不自动修改 dmit 服务器配置。
- 不新增告警或后台 UI。

## Decisions

- 文档采用“推荐值 + 作用 + 副作用 + 何时调大”的格式，避免只给配置片段无法判断取舍。
- 示例配置以 2GiB 级别机器为基准：Nginx 80m、`GOMEMLIMIT` 约 600-700MiB、`GOGC` 75、上游响应和 SSE 行上限收紧、usage worker 池降并发。
- 验证清单复用本次排查命令思路，但写成安全的只读步骤，不包含敏感日志正文。

## Risks / Trade-offs

- 低内存推荐值可能影响超大非流式响应或图片场景 → 文档明确副作用和调大条件。
- 不改默认值意味着新部署仍可能沿用宽松默认 → 在部署文档和知识库入口增加醒目引用。
