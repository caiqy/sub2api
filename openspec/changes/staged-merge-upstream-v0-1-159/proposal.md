## Why

本 change 已完成 `v0.1.152`、`v0.1.153`、`v0.1.155`、`v0.1.156` 四段合并、full verify 和本地 `v0.1.156.1` 发布，但尚未归档。上游随后发布 `v0.1.157`、`v0.1.158`、`v0.1.159`，继续大幅修改网关、调度、安全、计费、图片、生成代码和 migrations；需要在保留首轮证据的基础上追加三段集成并重新验证。

## What Changes

- 保留首轮 23 项完成状态、四个 merge 节点、能力矩阵和 `v0.1.156` 验证报告作为历史证据；扩展范围使旧 `verify_result=pass` 失效。
- 在新的 merge 前门禁中重新运行当前分支的完整测试、前端 build 和 Ent/Wire 生成稳定性检查，并把三段 changed files 映射到既有能力矩阵。
- 依次使用 `--no-ff` 合入 `v0.1.157`、`v0.1.158`、`v0.1.159`，每段记录冲突决策、修复回归并通过独立阶段门禁。
- 对无文本冲突的调用链、配置、生成代码和 migration 进行能力级审查；除明确例外外，本地能力不得回归，无法共存时暂停等待用户决定。
- **BREAKING** 首轮在 `v0.1.156` 阶段完成的本地 `openai-first-token-timeout` 移除继续有效；后续 tag 不得恢复旧实现或兼容别名。
- 最终将本地版本规范为 `0.1.159.1`，执行后端与前端全量门禁、生成代码一致性、migration、冲突标记、Git 祖先关系及能力矩阵验证；不包含推送、发布或部署。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `upstream-release-sync`: 将已验证但未归档的分段合并继续扩展到后续正式 tag，并要求旧证据只作为历史基线、新范围重新通过逐段与最终验证。
- `openai-first-token-timeout`: 保持本地首 Token 超时契约已移除，并跟随后续 release 对上游原生首输出行为的演进。

## Impact

- Git 历史：在既有四个 merge 节点后新增三个按顺序关联正式 tag 的 merge 节点，以及必要的本地兼容修复提交。
- 后端：新增重点包括异步图片任务与对象存储、图片输入计费、上游计费倍率与 scheduler、操作审计、会话绑定/step-up、Grok/Responses/WS、分组复制、用户批量限额和客户端 IP 解析。
- 前端：新增重点包括审计管理、账号计费倍率、Grok 端点、分组复制、用户批量限额、DataTable、账号上游链接和 Stripe 懒加载。
- 配置与 API：保留上游首输出配置；复核安全、审计、图片存储和计费新增配置/API，不恢复已删除的本地首 Token 运行时设置。
- 验证：首轮报告保持只读，新增 `v0.1.159` 扩展验证报告、三段门禁和最终 full verify 证据。
