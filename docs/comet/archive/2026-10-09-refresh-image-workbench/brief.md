# 目标

基于 GitHub GPT Image 项目的源码调研，重做 Sub2API 用户端 `/images` 创作工作台：让日常生成、参考图编辑、等待反馈和历史复用形成完整流程，同时消除历史列表逐条读取完整图片详情的性能瓶颈。

# 范围

- 保留 Vue 3、Tailwind、项目公共组件、青色品牌和明暗主题；桌面为左侧创作输入、右侧图片预览，移动端纵向排列。高级参数折叠，历史区域按需展开。
- 使用用户已有平台 API Key 和现有同步 Images 网关，不新增独立认证、计费或任务系统。按 Key 获取 `/v1/models` 的图片候选，并区分配置可见性与实际上游资格；模型发现失败可以明确重试，不通过生成请求探测资格。
- 支持模型对应的尺寸、质量、背景和输出格式；新模型在 Key 可见时可选，旧模型不收到专属新质量参数。保持一次生成一张的现有默认，不新增批量调度。
- 使用 fetch 读取标准 Images partial/completed/error SSE，兼容普通 JSON 响应；显示耗时、渐进预览和最终结果，提供停止等待。失败保留输入和已经完成的结果，不自动重新提交付费请求。
- 支持多参考图、上传蒙版、当前或历史可用结果送入编辑、预览和下载。参考图验证真实 MIME、文件大小、数量和可解码性；蒙版为有 alpha 的 PNG、与第一张参考图同尺寸且小于 4,000,000 字节；本地参考图每张不超过当前网关 20 MiB part 限制，最多 16 张，还受现有总请求体限制约束。
- 补齐历史页码、总数和 Key/生成编辑/状态筛选；图片详情点击后才读取，打开工作台不加载历史图片；处理请求竞态和重复读取。
- 历史服务按本页已授权 ID 一次批量读取有界请求摘要，不再逐条读取完整详情，也不批量读取完整图片响应。列表仅加载所需 API Key 关联；保留 PostgreSQL 14+ 兼容，不新增数据库迁移。
- 修复生产 request_body_preview 摘要解封与 multipart 提示词被主动清空的问题；列表短摘要与详情完整参数分离；补齐现有保留范围内 SSE 最终图片、URL 图片及详情已清理/链接失效的状态。

# 非目标

- 刷新后任务续查、跨服务重启恢复、异步队列、上游真正取消、百分比进度和逐图批任务调度。
- 长期图片资产系统、永久图库、参考图云端持久化、网页涂抹蒙版画布、聊天会话或 Responses 服务器多轮上下文。
- 自动重试生图、资格探测付费请求、生产部署、替换全站设计系统、增加新的第三方依赖或抬高 PostgreSQL 最低版本。
- 不修改原始 Local 工作区，不自动提交、合并、推送、清理或归档；最终交付由 DSH 隔离工作区验收条处理。

# 验收示例

- A1：`/images` 提供左输入右预览的桌面工作台和移动端纵向布局；高级参数及历史可展开；青色品牌、明暗主题、键盘操作、焦点与图片预览对话框可用，既有页面入口保留。
- A2：Key 选择保留分页可达性，按当前 Key 获取图片模型；切换 Key 时旧响应不覆盖新结果。空候选、发现失败及重试具有明确状态；不声称配置候选等于远程资格，不向浏览器暴露上游账号密钥。
- A3：画面比例提供默认“自动”（请求 size=auto）以及手动比例/尺寸；自动由模型选择输出尺寸，不保证匹配参考图。质量、尺寸、背景与输出格式根据已知模型限制校验；2.5 专属质量不发给旧模型，透明 JPEG 被阻止或改为兼容格式；默认一次一张，历史参数复用后仍重新校验。
- A4：生成和编辑兼容 JSON 与两种 Images SSE 事件；UTF-8 分块、CRLF、多行 data、注释心跳和无 `[DONE]` 的正常结束均可处理，partial 即时预览且最终图才计成功。
- A5：仅 partial 后断流、错误事件、JSON 错误及停止等待均有准确状态，保留输入和已完成结果；停止等待明确提示上游可能继续及计费；过期请求不覆盖新请求，不自动重试付费操作。
- A6：编辑支持最多 16 张参考图和上传蒙版；非法 MIME、超限数量/大小、不能解码的图片、非 PNG 或无 alpha 蒙版、蒙版与第一图尺寸不一致时拒绝提交并指出原因，遵守现有总请求体限制。
- A7：可用生成或历史结果可预览、以正确 MIME/扩展名下载并送入编辑；送入编辑只填写参考图和参数、不自动提交。外部 URL 不能读取、签名已失效或浏览器跨域受限时给出可操作错误，不绕过 URL 安全检查。
- A8：历史列表支持默认 20 条分页、总数和 Key/模式/状态筛选；详情点击后加载；首次工作台打开不请求历史详情，筛选/翻页竞态不会覆盖当前页，已完成生成不为匹配耗时而强制读取历史。
- A9：非空历史页在列表仓储内至多 5 次数据库查询（分页 count/详情表检查/记录、API Key 关联、一次摘要查询），20 与 50 条页不出现 2N 详情查询；不选择 response/upstream_response 正文。有效请求正文投影最多 256 KiB、相应头最多 8 KiB，列表提示词最多 256 个 Unicode 字符；旧超大请求列表降级为摘要不可用而不影响单条详情路径。测试同时包含大图片响应、dataURL 源图和旧 multipart。
- A10：历史共享解析器正确处理原始 JSON、request_body_preview envelope、有界原始 multipart 和新的编辑摘要；新 multipart 记录保留提示词和参数。已丢失提示词的旧记录不伪造内容；超界非空 request 不被误当作空值回退读取上游大正文；非法/截断内容不导致整页失败。
- A11：现有保留范围内的 JSON/base64、URL 与 SSE 最终图可在详情预览和复用，partial 不成为历史成功图片；详情已清理与链接不可用有明确状态，历史编辑参数回放提示重新上传原始参考图/蒙版，并说明全站共享的详情保留策略，不承诺永久图库。
- A12：历史列表批量查询与详情读取保持用户所有权及 Key 过滤权限；复用原网关鉴权、调度、审核、配额与计费，不改变上游转发的核心资格判定。定向前后端回归、查询/负载检查、类型检查与生产构建有真实结果，最终由新的只读 Verifier 核对所有验收项；真实付费上游验证未执行时如实说明。

# 关键决定

- 第一轮用户要求按推荐方向执行；第二轮用户选择 Q3=A、Q4=A、Q5=A（追加列表加载性能）、Q6=A。
- 单个 Native change，按列表与摘要修复 → 流式调用与表单 → 工作台整合 → Runtime 检查及独立 Verify 顺序实施。各部分共享图片契约和页面，拆 Supervisor 会增加工作区和集成成本，因此不拆子任务。
- GitHub 项目仅作交互/协议参考，不照搬 React/Next、BYOK 认证或自动重试矩阵；已有 Vue/Go 能力优先。
