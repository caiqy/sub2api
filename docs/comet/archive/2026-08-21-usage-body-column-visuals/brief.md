# Outcome

管理员使用记录表将“体积”列改名为“请求体”，并放到“费用”之后、“延迟”之前。请求体列左侧竖条按请求体大小显示与延迟列一致的绿、黄、橙、红色阶。

# Scope

- 调整管理员使用记录表的列顺序和中文列名。
- 保留请求体输入、输出、总计三行数据展示。
- 请求体大小按二进制 MiB 分档：`<=1 MiB` 绿色，`>1 MiB 且 <=2 MiB` 黄色，`>2 MiB 且 <=4 MiB` 橙色，`>4 MiB` 红色。
- 请求体大小为空、无效或负数时，竖条显示中性灰，数值继续显示 `-`。

# Non-goals

- 不修改后端字段、接口、数据计算或数据库。
- 不修改请求体/响应体数值、导出内容、延迟色条规则或其他页面功能。

# Acceptance examples

- A1：管理员使用记录表的可见列顺序为 `TOKEN → 费用 → 请求体 → 延迟 → 时间`，列名显示“请求体”。
- A2：请求体列仍显示输入、输出、总计三行，已有有效值按原格式展示，缺失值显示 `-`。
- A3：请求体大小 `0`、`1 MiB`、`2 MiB`、`4 MiB` 和超过 `4 MiB` 时，左侧竖条分别落在绿色、绿色、黄色、橙色和红色色阶；色阶与延迟列使用同一套颜色语义。
- A4：请求体大小为空、非有限数或负数时，左侧竖条为中性灰，不误显示为绿色；延迟列现有首字/总耗时色条行为保持不变。
- A5：前端类型检查、Lint 和相关单测通过。

# Constraints and invariants

- 二进制阈值使用 `1024 * 1024`，与现有 `formatBytes` 的单位规则一致。
- 仅管理员使用记录表调整列顺序；共享表格组件的既有数据渲染能力保持兼容。
- 不新增依赖。

# Decisions

- 使用四个固定大小区间复用延迟列现有的绿、黄、橙、红色阶，保证扫描语义一致并保持实现简单。
- `1 MiB` 作为绿色上限；只有严格超过 `1 MiB` 才进入黄色区间。

# Open questions

无。

# Verification expectations

- 运行前端相关测试、TypeScript 类型检查、Lint 和生产构建或项目现有等价检查。
- 检查列顺序、文案、四档边界、缺失值颜色以及延迟列回归行为。
