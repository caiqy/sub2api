# Subscription quota cycle

## 用户自助提前重置

系统应允许订阅所有者在当前有效订阅的额度已经耗尽时，主动提前结束当前额度周期，并以扣减订阅有效期为代价立即开始新的额度周期。

### 资格校验

- 订阅必须属于当前登录用户且仍处于有效状态。
- 至少一个配置了正数限额的日、周或月额度窗口，其当前用量必须已经达到或超过限额。
- 额度尚未耗尽时不得执行提前重置。
- 扣减后订阅必须仍然有效，否则拒绝操作且不修改任何数据。
- 一次性日额度订阅没有可交换的后续日周期，不得作为可提前重置的日窗口。

### 确认信息

用户提交前必须看到确认弹窗。弹窗应展示订阅名称，并以只读方式列出当前全部已耗尽且可提前重置的日、周、月额度窗口，不得允许用户排除其中任一窗口。

弹窗应展示每个窗口距离正常重置点的剩余时间、本次最终扣减时长、预计操作后到期时间，并说明操作立即生效且不可撤销。

用户取消时不得发起权益变更请求。

若扣减后订阅无法保持有效，订阅页面仍应展示提前重置入口，弹窗应展示本次窗口、所需扣减和有效期不足原因，并禁用确认操作。

### 原子更新

前端应提交弹窗展示并经用户确认的日、周、月窗口集合，不得提交或决定有效期扣减值。

后端必须在行锁后根据当前数据库状态重新计算全部已耗尽且可提前重置的窗口。请求确认集合必须与后端计算集合完全一致；请求缺少窗口、包含不再耗尽的窗口，或并发变化导致集合不一致时，后端必须整笔拒绝，不得静默增加窗口或扩大扣减。

集合一致时，后端必须在单个事务中完成有效期扣减、全部耗尽窗口用量归零及窗口起点更新。新窗口从操作成功时开始，不沿用管理员重置到当天零点的规则。事务提交后必须失效相关订阅与计费缓存。

任何校验或写入失败都不得留下部分更新。接口必须具备重复请求保护，并在并发请求下重新锁定和校验订阅，使同一批已耗尽窗口最多成功提前重置一次。

### 周期扣减规则

系统应分别计算全部已耗尽窗口距离其正常重置点的剩余时间，并取其中最大值作为本次有效期扣减值，不得累加彼此重叠的时间。新到期时间等于原到期时间减去该最大值，全部新额度窗口从操作成功时间开始。

例如日窗口距离正常重置还有 23 小时、周窗口还有 6 天 23 小时且两者均耗尽时，本次必须同时重置日和周，到期时间应提前 6 天 23 小时。

### 响应与页面状态

成功响应应返回更新后的订阅，使页面立即展示全部已重置额度窗口和新到期时间。失败响应应提供可展示的原因，页面保留原状态。

用户订阅页面只要存在至少一个已耗尽且可提前重置的窗口就应展示操作入口。请求进行期间操作不可重复触发。

确认集合与后端当前状态不一致时，页面应提示额度状态已变化，需要重新打开确认弹窗。

## 兼容性

管理员现有手动重置额度与调整有效期行为保持不变。该能力不触发支付、退款或自动续费。

旧客户端提交部分已耗尽窗口时，后端必须拒绝请求，不得按超过客户端已展示的时长扣减有效期。
