# Outcome

防止用户提前重置部分额度窗口后被扣减订阅有效期却仍无法使用：一次操作必须重置当前全部已耗尽窗口，并保证用户确认的扣减影响与后端实际执行一致。

# Scope

- 确认弹窗直接展示本次全部已耗尽窗口，不再允许逐项选择。
- 后端行锁后重新计算全部已耗尽窗口，并与用户确认时提交的窗口集合严格比对。
- 有效期不足时保留入口和影响说明，但禁止确认；后端绕过前端时仍整笔拒绝。
- 更新前后端自动化测试，覆盖全部窗口重置、状态变化和有效期不足。

# Non-goals

- 不修改管理员重置额度、支付、退款或自动续费行为。
- 不改造现有事务、幂等 receipt 或缓存失效架构。
- 不新增 API 路径、预览接口、确认 token 或数据库 migration。

# Acceptance examples

- 日额度还剩 23 小时正常重置、周额度还剩 6 天 23 小时正常重置且两者均耗尽时，弹窗直接列出日和周；确认后同时重置两者，并扣减 6 天 23 小时有效期。
- 旧页面只提交日窗口，或弹窗打开后耗尽窗口集合发生变化时，后端整笔拒绝且不修改有效期和任何额度窗口。
- 全部耗尽窗口需要扣减 6 天，但订阅只剩 3 天时，入口仍可打开并展示影响，确认按钮禁用；直接调用接口也不修改数据。
- 用户取消弹窗时不发起权益变更请求。

# Constraints and invariants

- 后端必须以行锁后的数据库状态为准，不能静默补齐窗口并扩大用户未确认的扣减。
- 成功操作后不得遗留任何已耗尽窗口继续阻塞用户。
- 最终扣减时长取全部已耗尽窗口正常重置剩余时间的最大值，不累加重叠时间。
- 所有拒绝路径必须发生在权益写入前，不留下部分更新。

# Decisions

- 用户确认一次提前重置必须覆盖当前全部已耗尽窗口。
- 弹窗只读展示本次窗口集合，不再提供复选框。
- 请求保留现有日、周、月字段作为用户确认快照；后端重算集合后严格比对，不一致则拒绝。
- 有效期不足时保留入口并说明原因，前端禁用确认，后端继续最终校验。
- 仅修改部分重置语义及对应界面、校验和测试，复用现有权益更新机制。

# Open questions

无。

# Verification expectations

- 后端单元测试覆盖部分集合拒绝、全部集合成功、三窗口最长扣减、状态变化和有效期不足。
- 前端测试覆盖只读窗口列表、全部窗口请求、有效期不足提示与禁用确认。
- 运行后端相关测试、前端相关测试、typecheck、lint 和构建。
