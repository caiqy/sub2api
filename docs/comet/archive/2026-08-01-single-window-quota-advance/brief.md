# Outcome

将用户自助额度提前重置限制为恰好一个窗口达到提前重置门槛的场景。门槛固定为距离该窗口限额不超过 1 美元；用户用该窗口距自然重置的剩余时间等额换取立即开始的新周期。多个窗口同时达到门槛时不允许操作，从而移除现有“全部耗尽窗口一起重置并按最长剩余时间扣减”的不公平语义。

# Scope

- 后端在事务行锁后重新计算日、周、月可提前重置窗口，只允许实际集合恰好包含一个窗口且与请求一致。
- 日、周、月窗口均以 `usage >= max(limit - 1, 0)` 判断是否达到提前重置门槛，前后端保持一致。
- 多个可提前重置窗口同时达到门槛时，后端返回明确冲突错误，前端隐藏操作入口并说明需等待自然重置。
- 单窗口成功时仅清零该窗口用量、将该窗口起点设为操作时刻，并从订阅有效期扣减该窗口距自然重置点的剩余时间。
- 前端预览和确认弹窗仅在恰好一个窗口达到门槛时允许提交；有效期不足时仍可查看预览但不能确认。
- 同步更新中英文文案、后端单元测试、前端工具与组件测试，以及受新资格规则影响的缓存失效测试。
- 将 `subscription-quota-cycle` canonical capability 完整替换为单窗口语义。
- 审查修复仅处理三项：使用 machine epsilon 消除固定 1 美元门槛的浮点边界假阴性；恢复撤销订阅提交后的即时 versioned Redis tombstone 与跨实例发布，同时保留 outbox 重试；移除额度提前重置事务内多余的刷新读取并恢复 integration 测试语义。

# Non-goals

- 不修改管理员手动重置额度或调整有效期的行为。
- 不修改正常额度拦截或计费规则；1 美元容差仅适用于用户自助提前重置资格。
- 不修改支付、退款、自动续费、事务、幂等 receipt 或缓存失效架构。
- 不支持多窗口按比例扣减、选择部分窗口重置或可变周期。
- 不恢复多窗口复选框。
- 本轮不扩展提前重置请求契约，不增加确认窗口起点或订阅版本字段。

# Deferred known issue

- 当 `0 < limit <= 1` 时，新周期零用量仍按既定规则立即达到门槛；用户基于新周期重新打开弹窗并再次确认后，允许继续提前重置。
- 两个不同幂等键若都基于同一旧窗口确认，第一次成功后第二次可能作用于同类型的新周期。修复该问题需要请求携带窗口身份；用户已明确选择本轮暂不修改请求契约，因此该问题保留，不得在本轮以改变零用量资格的方式规避。

# Acceptance examples

- 限额为 80 美元的日窗口用量达到 79 美元，且周、月窗口未达到各自门槛时，用户可确认提前重置；低于 79 美元时不提供该操作。
- 正数限额不超过 1 美元的窗口门槛为 0，因此零用量也可以成为唯一可提前重置窗口；非正数限额仍表示未配置额度，不参与判断。
- 周或月窗口单独达到门槛时，系统以同样规则只重置该窗口，其他窗口用量和起点保持不变。
- 两个或三个可提前重置窗口同时达到门槛时，页面不显示重置按钮，显示等待自然重置的原因；直接 API 请求返回 `QUOTA_ADVANCE_MULTIPLE_WINDOWS` 且数据不变。
- 弹窗被直接传入多窗口订阅时，确认按钮保持禁用且不会发出请求。
- 用户打开单窗口确认后，若锁后实际达到门槛的窗口集合与请求不一致，后端返回 `QUOTA_ADVANCE_STATE_CHANGED` 且不产生部分更新。
- 单窗口所需扣减会使订阅立即失效时，页面仍提供入口和预览，但确认按钮禁用；绕过前端的请求仍由后端拒绝。
- 一次性日额度不计入可提前重置窗口，也不能作为请求窗口。

# Constraints and invariants

- 资格与扣减值必须由后端基于行锁后的数据库状态计算，前端不得提交扣减时长。
- 正数限额窗口的提前重置门槛固定为 `max(limit - 1, 0)` 美元，不新增套餐配置项。
- 一次操作最多重置一个日、周或月窗口。
- 成功事务必须原子完成有效期扣减、目标窗口用量归零和窗口起点更新；失败不得留下部分写入。
- 新窗口从操作成功时开始完整周期，不沿用管理员重置到当天零点的规则。
- 扣减后订阅必须仍在操作时刻之后有效。
- 现有所有者校验、幂等保护、并发锁定和提交后缓存失效保持不变。

# Decisions

- 单窗口是唯一支持的用户自助提前重置模型；多窗口没有公平的固定周期扣减方案，因此明确拒绝。
- 多窗口错误使用 HTTP 409 冲突码 `QUOTA_ADVANCE_MULTIPLE_WINDOWS`；请求与锁后实际单窗口不一致继续使用 `QUOTA_ADVANCE_STATE_CHANGED`。
- 前端 `getQuotaAdvancePreview` 仅在达到提前重置门槛的窗口数恰为一时生成预览，删除多窗口取最大剩余时间的旧逻辑。
- 页面依据本地达到门槛的窗口数显示多窗口说明；后端错误覆盖过期页面状态、并发变化和直接 API 请求。
- 用户确认日、周、月窗口统一使用固定 1 美元容差；正数限额不超过 1 美元时门槛为 0，允许零用量提前重置。
- 该容差只改变用户自助提前重置资格，不改变正常额度耗尽、拦截或计费定义。
- 浮点比较仅允许覆盖 binary64 表示误差，不新增可感知的美元业务容差；`limit=1.10, usage=0.10` 必须按十进制业务语义达到门槛。
- 撤销订阅必须在数据库提交后立即执行带权威行版本的 Redis tombstone 和跨实例发布；数据库 outbox 继续作为失败重试，不得成为唯一即时失效路径。
- 额度提前重置更新后的内存对象已包含数据库行版本和响应字段，不再执行额外事务内回读；任一前置写入失败仍整体回滚。
- 用户已审阅 2026-08-01 全面审查结论，并明确授权修复浮点边界、撤销订阅即时失效和多余事务内回读；窗口身份请求契约留待后续决定。

# Verification expectations

- 后端定向及全量 unit tests 通过，覆盖 1 美元门槛边界、小额限额零用量、日/周/月单窗口成功、多窗口拒绝、状态变化、一次性日额度和有效期不足。
- 前端 Vitest 通过，覆盖同一门槛边界、单窗口入口与提交、多窗口提示与禁用、预览和有效期不足。
- 门槛测试必须使用独立输入 `limit=1.10, usage=0.10`，不得只用 `usage = limit - 1` 构造同源浮点值。
- 撤销订阅测试必须证明提交后立即调用 versioned tombstone 与跨实例发布，并保留 outbox 的最终重试路径。
- PostgreSQL integration 测试不得再以事务内 `GetByID` 必然失败却期望成功的矛盾 stub 验证刷新读取。
- 前端 typecheck、lint、build 通过。
- `git diff --check` 通过。
- 本机无 Docker 时如实记录 PostgreSQL/Redis integration tests 未执行，不得声明其通过。
