# Outcome

为Sub2API新增输入请求体流量费，计费单位$/MB。用户主动授权后可发送超过免费软门槛的输入，费用可核对并纳入现有账单。先grilling确认设计，再由Comet Native实施、Runtime检查与独立Verifier验收。

# Scope

- 系统设置→功能开关：流量计费总开关、起步包大小（输入请求体，MB）、单价（$/MB）。
- 个人资料：默认关闭的“启用超大请求体并接受流量费（xxx $/MB）”。
- 同步HTTP既有计费路径、同步图片/音频、OpenAI Responses WS按轮；Grok realtime按整连接方案随本次完整Shape确认。
- 管理员和用户共享使用记录费用明细新增流量费与问号提示，合计/实扣/消费汇总包含流量费；已有导出总费用同步，不扩充导出分项。
- 排除全部批处理与异步任务（包括异步图片、批量图片、异步视频及其后续查询/下载结算）。排除路径不新增收费、不应用本次授权门槛，保留既有准入和模型计费。

## 目录结构

### 新建

- backend/migrations/ — 按现有迁移约定增加用户授权和用量计费依据；以仓库实际迁移目录为准。
- backend/internal/service/、backend/internal/handler/ — 最小的流量计费/准入和结算回归测试，覆盖实际路径，复用现有测试工具。

### 修改

- backend/internal/server/routes/、backend/internal/server/middleware/ — 计费路径识别、准入与既有输入尺寸采集协作，明确排除任务入口。
- backend/internal/handler/ — 各同步入口及WS开始时输入/策略快照、个人资料、系统设置和DTO。
- backend/internal/service/ — 系统配置、用户授权与鉴权缓存、费用分项、请求预占、幂等结算、WS正常终态与客户端断流判定。
- backend/internal/repository/、backend/ent/ — 用户授权与用量依据持久化、金额/配额/统计映射，隔离上游账号成本。
- frontend/src/views/user/ProfileView.vue、frontend/src/components/user/profile/ — 授权开关、当前单价及简明收费说明。
- frontend/src/views/admin/SettingsView.vue — 总开关、阈值与单价表单。
- frontend/src/components/admin/usage/UsageTable.vue — 共享费用明细、可悬停/聚焦问号、输入字节换算与公式。
- frontend/src/ — 关联API、类型、多语言和既有总费用汇总/导出映射，沿用当前目录组织。

### 明确不建

- 独立流量计费服务或新计量依赖 — 在既有请求/结算链加入输入标量与费用分项即可。
- 批处理/异步流量快照、任务补偿、视频后台主动结算 — 已明确排除。
- 新网络抓包计量系统 — 沿用应用层body口径。

# Non-goals

- 不按响应体收费，不改原有输入/输出/总计（输入+输出）展示。
- 不提高任何既有服务器/路由/解压/multipart/WS硬上限。
- 不给原非计费查询、token计数或无既有账单接口新增账单。
- 不增加Excel/CSV流量分项或依据列；不改变模型定价、模型倍率和模型失败时原有扣费。
- 不发布版本、不部署、不推送、不创建PR；Git外部交付未授权。

# Decisions

## 已确认业务决定

- Q1/Q2/Q5修订：S仅输入请求体字节，T为输入触发阈值；S≤T免费，S>T收费S×2÷1,000,000×P美元。1 MB=1,000,000 bytes，不扣阈值、不凑整MB；响应无关。Q5早期输入+响应方案已被用户后续明确修正覆盖。
- Q3/Q14：仅最终成功、完整正常结束且输入尺寸可知时收流量费；失败、超时、客户端流式中断免收；内部重试一次请求只收一次。输入未知不估算收费，记录原因；响应未知无关，模型费沿原规则。
- Q4：个人授权新老用户默认关闭；开启即接受后续系统单价，无涨价重新授权。
- Q6：全局关闭维持既有准入、不收流量费；全局开且个人关时S>T转发前HTTP413，traffic_billing_consent_required，附阈值、当前单价和资料页开启提示，不转发、不扣费；S≤T放行免费。两开关均开时允许突破软门槛，成功后收费。升级后的WS使用协议内错误，不能返回HTTP状态。
- Q7/Q18：流量分项原价=实扣，不乘用户/分组/高峰等倍率；模型价格或倍率为0不免流量费。
- Q8/Q9：与同一请求模型费使用同一订阅/余额来源，并计入适用用户/Key额度及消费限制；不增加上游账号成本、账号额度或账号统计费用。
- Q11：每次请求/WS轮开始冻结开关、授权、阈值、单价及输入字节，保存计费依据与金额；运行中调价或切换授权不改变已开始单位；历史不重算。实时语音整连接方案以连接开始冻结配置、结束保存累计输入。
- Q12：初始全局关闭、阈值10 MB、单价0；阈值须正数、单价非负且有限，开启全局收费要求正单价，服务端和前端都校验。
- Q13：沿用现有应用层输入尺寸，可为解压后或协议转换后的有效body，不含headers/TLS，不改为网络实测；费用明细提供精确字节与十进制MB换算，原尺寸显示单位不改变。
- Q15/Q17：管理员与用户共享流量明细，原尺寸总计保留；总原价、实扣、消费汇总、已有导出总额一致，不新建导出分项。
- Q16：所有既有硬上限保持，包括默认文本32MiB/总体256MiB、解压64MiB、multipart单项20MiB和WS限制，各路径按现有配置生效。
- Q10已被后续范围修订覆盖；Q21-Q23随排除异步/批处理移出范围。Q24确认这些排除路径同时免新增软门槛。

## 本次完整Shape待确认提案

simple此前被跳过，用户随后询问含义：已解释为系统现有简易运行模式，与截图Standard服务档位不同，沿用既有扣款语义的提案等待完整Shape确认。实时语音方案已在用户后续回复“2.同意”中明确接受：
- simple模式沿用本次同步链现有语义：普通simple仅记录费用，不扣余额/订阅；simple Key窗口特例仅计入窗口。标准模式正常收费。批处理已经排除，不改其simple行为。
- Grok实时语音沿用整连接一账单，累计客户端输入消息payload（控制消息亦属实际输入，不含WS帧开销），配置/授权在连接开始冻结。有既有可结算音频且正常关闭1000才收一次流量费；1001/1005/1006等其他关闭免流量费，模型费用仍按既有规则。未授权连接在下一条输入将使累计S>T时发送协议内授权错误并关闭连接，流量费不收。已授权仍保留现有单帧/其他硬限制；OpenAI Responses WS仍逐轮独立判断。

## 实施依据与策略

- Comet Native traffic-billing，current/main工作区；当前仅Shape。宿主具备与Builder分离的独立Verifier会话能力。
- 使用单个change：准入、输入快照和结算共用核心区域，拆分增加协调成本，不创建Supervisor子任务。
- 现有尺寸可能在日志插入才补齐，需在body提前释放前冻结输入标量；不可到结算时读取已释放body，也不可误取响应/查询body。
- 授权需贯通用户字段掩码、Ent/投影、API Key鉴权快照双向映射、版本及用户全Key失效。关闭后新请求立即使用新授权。
- 复用现有预占与结算幂等；流量费加入用户结算和适用额度，账号成本继续使用纯模型费用。模型费0也不能使订阅请求错误回落余额。
- OpenAI WS上游completed不等于客户端完整接收；断线drain、failed/incomplete/cancelled和部分图片成功保留模型账单时均不得误收流量费。
- 历史记录使用新增金额默认0、计费依据可空，不追溯扣旧请求；未知输入明确标原因。

# Acceptance examples

- A1：升级后新老用户个人授权为关，总开关关、T=10 MB、P=0；未配置正价格不能开启总开关，非法/非有限配置被服务端拒绝。
- A2：全局关时现有同步请求准入与扣费不新增限制；全局开且个人关时S=T放行免费、S>T返回413与授权错误且不访问上游、不扣款；已授权仍被原硬上限限制。
- A3：T=10 MB、P=0.01 $/MB时，输入10,000,000字节流量费0，输入12,000,000字节流量费0.24美元，响应任意大小不改变结果；小数字节按比例，无整MB进位。
- A4：改变模型价或用户/分组/高峰倍率不改变同样输入对应流量费；模型价0或倍率0仍可收0.24美元，账号成本/额度不包含这0.24美元。
- A5：模型费和流量费使用同一订阅/余额来源，总额、实际扣款、用户/Key消费限制、消费汇总一致，模型费0的订阅请求仍走订阅，不回落余额。
- A6：失败、超时、客户端流式断开、输入未知无流量扣款；正常成功一次请求收费一次，多次内部重试/重复结算不重复，模型原有费用保留；输入未知留有原因。
- A7：请求开始后调价、改阈值、切换开关不改变本单位金额；下一请求使用新配置/授权。历史依据可复算、旧记录为0且不被追扣，用户授权变更使鉴权缓存失效。
- A8：同步各平台文本/图片/音频入口与别名适用同规则；批处理、异步图片、异步视频及其状态/下载结算不收流量费、不执行新授权门槛，原模型费与硬限制保持。
- A9：OpenAI Responses WS按每轮原始客户端payload判断准入、冻结并结算；异常终态、客户端断流drain、部分图片模型成功例外不误收流量费，升级后错误通过协议发送。
- A10：Grok实时语音按本次提案的整连接累计输入，在正常1000关闭且有既有可结算音频时收一次；异常关闭免流量费，未授权累计超阈值时协议报错并关闭，模型费保持原规则。
- A11：simple普通路径仅记流量费不扣余额/订阅，simple Key窗口模式仅纳入窗口；标准模式同样输入按规则实际收费。
- A12：个人资料显示当前价格与默认关闭开关；管理员功能开关表单可保存合法设置；管理员/用户账单均显示流量费、精确输入计费依据和可鼠标悬停/键盘聚焦的问号提示“包含接收和发送双边流量”；总费用与导出已有总额一致，不新增导出分项，原输入/输出/总计展示保留。

# Verification expectations

- 金额/阈值、准入与硬限制、倍率隔离、订阅/余额/额度/账号成本、鉴权缓存及幂等最小回归。
- 同步HTTP平台/入口矩阵、WS每轮与断流、Grok realtime会话、明确排除任务路径的针对性验证。
- 后端相关包测试与前端类型/构建；用真实浏览器验证设置、资料、共享费用tooltip的鼠标和键盘交互，未执行的检查如实标记。
- Runtime检查后新的只读Verifier独立核对全部A1-A12；失败回Build修复，验收通过后等待用户接受结果。
- 如启动临时PostgreSQL/Redis仅清理本任务实例并验证端口，不影响原有服务；不可用检查不得伪报通过。
