# 目标

- 为 OpenAI 账号提供独立的 ModelTrace 自动检测频率配置，并可选择在检测结论为降智时进入临时不可调用状态。

# 范围

- 账号创建与编辑、配置持久化及展示；自动检测资格与按账号间隔调度；检测结果驱动的临时状态及恢复；相关历史和状态展示。
- 沿用现有全局自动检测总开关、目标模型、轮次和手动检测入口；每个 OpenAI 账号可覆盖全局自动检测间隔，并可配置是否因降智暂时退出整个账号的业务调度。

# 非目标

- 不改变 ModelTrace 指纹评分方法，不把检测失败当作降智，不扩展到非 OpenAI 平台。

# 验收示例

- 两个自动检测已开启的账号按各自的有效间隔独立产生任务；未覆盖的账号继承全局间隔。
- 开启隔离策略的账号在手动或自动检测得到有效降智结论时退出整个账号业务调度；检测失败或超时不触发隔离。
- 因 ModelTrace 降智被隔离的账号仍按有效间隔参加自动复检；只有有效正常结论才恢复业务调用，失败和超时不解除隔离。
- 账号只按最新有效结论维持降智/正常隔离状态：模型 A 有效降智后，即使模型 B 有效正常，也解除 ModelTrace 隔离；任一模型后续有效降智则重新隔离。失败不改变状态。
- 关闭隔离策略立即撤销由 ModelTrace 设置的隔离；关闭自动检测则保留隔离，并允许手动检测恢复。其他独立的不可调用原因不受影响。

# 约束与不变量

- 当前全局间隔默认 60 分钟、允许 5–10080 分钟；后台每 30 秒扫描，按账号上次自动任务结束时间计算周期，手动任务不改变自动周期。
- 现有临时不可调用会同时排除业务调度和自动检测；引入降智隔离后须另行确定检测如何继续及何时解除。
- 既有正式规格要求检测仅观测、不控制调度；本次需求若确认隔离行为，将明确修订该条而保留未启用策略的行为。

# 决策

- 用户要求采用 grill-me 逐轮确认细节，本 change 在 Shape 澄清完毕前不修改实现。
- Q1：账号级间隔是可选覆盖，允许 5–10080 分钟；留空继承现有全局间隔，存量账号未设置时行为不变。
- Q2：手动和自动检测的有效降智结论均可触发隔离，失败或超时不触发。
- Q3：隔离作用于整个账号的业务调度，而非只作用于被检测的模型。
- Q4：降智隔离不因固定冷却期到期而自动恢复；允许已被 ModelTrace 隔离的账号继续按有效间隔复检，有效正常结论才恢复业务调度。复检失败维持隔离。
- Q5：关闭该账号的降智隔离策略时，立即解除仅由 ModelTrace 导致的隔离，不能清除其他不可调用原因。
- Q6：关闭全局或账号的自动检测开关不会解除已有的 ModelTrace 隔离；管理员仍可手动检测或关闭隔离策略。
- Q7：手动或自动的有效正常结论均可用于恢复，具体跨模型转换以 Q11 的确认结论为准。
- Q8（已被后续决定替代）：原先仅原目标模型正常才解除；用户随后明确要求账号隔离只保留降智/正常两种状态、不按模型区分。
- Q10：账号隔离不逐模型记录，也不累计多个降智模型；检测记录与评分仍按各次检测目标保留。
- Q11：账号隔离只由最新一次有效结论决定：手动或自动检测任意模型降智则隔离，任意模型正常则恢复，失败或超时不改变现有隔离；模型仍用于评分和历史。
