# Codex 客户端账号路由筛选完整规格

## Purpose

允许管理员选择将 OpenAI OAuth 账号现有的 Codex 客户端准入限制提前应用于业务路由，使不合格请求跳过此账号并继续使用同一授权范围内的其他合格资源。

## Requirements

### Requirement: 账号级父子开关与兼容

系统 SHALL 在 accounts.extra 中保存布尔字段 codex_cli_only_route_only。仅当账号是 OpenAI OAuth、codex_cli_only 为布尔 true、且新字段为布尔 true 时启用路由筛选。字段缺失、非法类型或 false 均视为关闭。父开关关闭时子开关不生效；非 OpenAI OAuth 账号不受新开关影响。关闭子开关继续保留现有选后客户端拦截。

#### Scenario: 默认与适用范围

Acceptance: A1

WHEN 检查不同账号类型、父开关和新字段的组合
THEN 仅 OpenAI OAuth 双开组合启用筛选，其余组合兼容原行为。

### Requirement: 请求级候选筛选

系统 SHALL 将现有客户端检测结论作为候选资格条件。不合格双开账号不参与本请求的有效候选竞争、最终并发占用、上游转发或新粘性绑定。其他账号仍按各自原有规则参与。筛选不允许增加跨分组、跨授权、跨模型或跨协议的候选。

#### Scenario: 混合账号池

Acceptance: A2

WHEN 非合格客户端进入包含双开账号 A 和可服务账号 B 的同一授权池
THEN 跳过 A 并选择 B；关闭 A 的子开关后恢复既有选后拦截语义。

### Requirement: 唯一客户端识别语义

系统 SHALL 复用现有 CodexClientRestrictionDetector 和全局策略。ForceCodexCLI 旁路、黑名单优先、官方身份、自由白名单、全局或账号 App Server 放行、官方候选版本可解析与上下界、引擎指纹和白名单指纹豁免均保持现有含义。路由基于客户端入站头和请求指纹，不以账号指纹收敛、身份伪装或协议转换后的官方字段重新识别。转发前现有安全检查保留。

#### Scenario: 策略一致

Acceptance: A3

WHEN 官方或第三方请求分别命中现有允许、拒绝、版本、指纹及全局旁路条件
THEN 路由筛选与 detector 结论一致，网关改写身份不能让原本不合格请求路由到双开账号。

### Requirement: 调度层、粘性和重选覆盖

系统 SHALL 在默认、分层和旧调度链的候选过滤、粘性命中、previous_response_id、影子账号、等待后复核、数据库刷新复核及 failover 重选时执行筛选。筛选不匹配仅影响本请求资格，不标记账号健康失败、全局暂停或消耗上游故障切换预算。具有不可迁移的上下文/所有者绑定时，沿用现有强绑定失败语义，不向被排除账号转发，也不进行破坏上下文的强制换号。

#### Scenario: 粘性与故障重选

Acceptance: A4

WHEN 请求粘性绑定不合格双开账号、发生重选或账号配置在等待中变化
THEN 所有调度方式均重新校验有效资格；只有安全可迁移的请求才使用其他合格账号，失败路径正确释放资源且不污染账号健康。

### Requirement: 网关入口与请求生命周期

系统 SHALL 覆盖可能选择 OpenAI OAuth 账号的业务网关入口，包含 Responses（含 compact）、Chat Completions、Messages 兼容和 WebSocket，以及其他实际可选择这类账号的业务端点。HTTP 使用入站请求头和相关 body 指纹；WS 选号使用握手头及首条生成消息，并在首次选号和故障重选保持一致。不新增连接内逐 turn 换号机制。筛选不能消费掉转发所需 body、额外长期保留完整大请求体或破坏既有句柄清理；仅保留请求生命周期内所需判定信息。缺少身份信息不能视为已匹配。

#### Scenario: HTTP 与 WS 入口

Acceptance: A5

WHEN 通过不同业务入口选号或在 WS 首次选号后重选
THEN 原始身份和指纹正确进入筛选，后续转发仍可读取完整业务请求且能按既有生命周期释放。

### Requirement: 空候选和原有错误语义

系统 SHALL 在筛选耗尽候选时使用当前端点既有无可用账号响应；不可迁移强绑定请求使用既有绑定失败响应。不因已过滤账号生成其选后 403。不启用子开关的其他账号仍可被原调度选中，并继续受其原选后拦截约束。本特性不承诺把所有账号的客户端拒绝统一改成容量错误。

#### Scenario: 没有合格账号

Acceptance: A6

WHEN 全部可路由账号被排除，或强绑定账号不合格
THEN 返回既有不可用/绑定失败结果，无不合格上游调用，授权、模型及协议边界完整。

### Requirement: 管理界面与配置生命周期

系统 SHALL 在创建、编辑和批量编辑 OpenAI OAuth 账号时提供“用于路由筛选”子开关，使用现有界面组件及中英翻译。说明打开后不符合客户端条件的请求跳过本账号、关闭后沿用选后拦截。创建和编辑中子开关从属于父开关，关闭父开关保存时清除有效子配置，避免孤立启用；默认关闭，切换账号和重置不残留值。批量编辑沿用现有兄弟子开关规则，同次显式批量开启父开关才可写入子字段，未选择更新不得覆盖现有配置。复制和重新授权等保留账号 extra 的流程继续保存新字段。

#### Scenario: 配置保存与回显

Acceptance: A7

WHEN 管理员创建、编辑、批量编辑、复制或重新授权账号
THEN 新字段默认、可见性、保存、回显和重置正确，中英文文案可用，未选择的批量字段不覆盖，配置在保留 extra 的操作中不丢失。

### Requirement: 可重复验证

系统 SHALL 留下使用仓库已有测试工具可运行的回归检查，覆盖配置组合、混合池、全部排除、粘性与重选、原始指纹以及前端更新 payload。必要的后端检查、前端类型检查和定向测试须记录实际结果，由独立 Verifier 核对所有验收项；失败或未运行不能标记通过。

#### Scenario: 完整验收

Acceptance: A8

WHEN 提交候选实现进行验收
THEN 当前候选具有可复核的检查记录，独立验收覆盖 A1–A8 和本规格，环境限制及未运行项目如实披露。

## Non-goals

不更改客户端识别标准或现有全局策略，不新增数据库迁移、依赖、全局路由框架、WS 逐 turn 换号或其他平台限制。不扩展管理测试/模型目录等非业务选号操作为新的客户端鉴权功能。不包含发布、推送和部署。
