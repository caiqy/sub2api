# Outcome

当用户的有效订阅额度耗尽时，用户可在订阅页面主动提前结束当前额度周期，以扣减订阅有效期为代价立即获得新周期额度；执行前必须通过确认弹窗明确展示影响。

# Scope

- 在用户订阅页面为符合条件的订阅提供“提前重置”操作。
- 确认弹窗展示将重置的额度、将扣减的订阅时长和操作后的到期时间，并要求用户明确确认。
- 新增仅允许订阅所有者调用的后端接口，原子完成资格校验、有效期扣减、额度窗口重置和缓存失效。
- 成功后刷新订阅额度与剩余有效期；失败时不产生部分扣减或部分重置。

# Non-goals

- 不改变管理员现有的免费手动重置额度能力。
- 不引入购买、支付、退款或自动续费流程。
- 不允许用户在额度尚未耗尽时提前囤积额度。

# Acceptance examples

- 有效订阅额度耗尽后，页面显示提前重置入口；打开弹窗可看到具体扣减时长、重置范围和新到期时间。
- 用户取消弹窗后，订阅有效期和额度均不变化。
- 用户确认且仍满足条件时，系统一次性扣减有效期并重置对应额度，页面展示更新后的结果。
- 请求重复提交、并发提交或服务端校验失败时，不会重复扣减，也不会只完成其中一部分更新。
- 非订阅所有者、失效订阅、额度未耗尽或扣减后无法保持有效的订阅不能执行操作。

# Constraints and invariants

- 所有权益变化必须由后端重新计算和校验，不能信任前端传入的扣减值或重置范围。
- 有效期扣减与额度重置必须处于同一事务，并具备重复请求保护。
- 弹窗必须在提交前说明操作不可撤销。
- 现有管理员重置接口及行为保持兼容。

# Decisions

- 用户明确要求使用 Comet 工作流开发。
- 用户操作必须经过说明效果的确认弹窗。
- 用户自助重置不是免费清零，必须扣减订阅有效期。
- 采用最小范围实现，不改造支付与管理员重置流程。
- 提前重置扣除当前周期距离正常重置点的剩余时间，而不是固定扣除一个完整周期；例如日额度还有 20 小时重置，则到期时间提前 20 小时。
- 多个额度窗口同时耗尽时，由用户在确认弹窗中逐项选择要重置的窗口；未选择的窗口保持原状，因此操作后仍可能受其限制。
- 同时选择多个已耗尽窗口时，有效期按各窗口距离正常重置点的剩余时间中的最大值扣减，不累加重叠时间。
- 确认弹窗中的额度窗口默认均不勾选，用户必须主动选择至少一项后才能确认。
- 用户已确认本 brief 与完整目标规格，可进入 Build。

# Open questions

无。

# Verification expectations

- 后端自动化测试覆盖成功、未耗尽、无权限、有效期不足、重复和并发请求。
- 前端测试覆盖入口条件、弹窗影响说明、取消以及确认后的刷新行为。
- 执行后端相关测试、前端类型检查和相关组件测试。
