# ModelTrace 降智检测规格

## Purpose

为 OpenAI 账号提供 ModelTrace 内容归因检测、全局及账号级自动调度、手动检测、检测历史和账号智商状态。检测模型始终来自当前 ModelTrace GPT 指纹列表；账号级覆盖只影响自动任务，实际探针直接调用所选模型。

## Requirements

### Requirement: 支持范围、模型目录与直接调用

ModelTrace 检测仅支持 OpenAI 平台的现有认证变体，包括 OAuth 订阅、API Key、Setup Token 及兼容的 OpenAI 认证路径；非 OpenAI 平台不展示配置和检测入口。服务器从当前 ModelTrace 指纹库生成 OpenAI 检测模型列表，只暴露 GPT 家族模型，不暴露 Claude 等其他评分候选。

管理员选择模型时，列表不按账号模型白名单、模型映射或当前模型发现结果过滤。服务端只校验所选模型属于当前 ModelTrace OpenAI GPT 列表。保存账号配置不要求该账号当前已经具备该模型映射或可调用能力。

手动和自动探针都使用所选账号的实际凭据归属、协议和业务代理，并直接将选择的模型 ID 发给该账号上游。ModelTrace 检测不使用账号模型映射替换目标，不回退全局模型或其他账号。上游拒绝、凭据缺失或协议不支持时记录失败，不静默换模型。检测历史记录选择模型和实际请求模型；普通业务请求仍使用既有模型映射规则。

#### Scenario: 账号和模型隔离

- **WHEN** 管理员选择某 OpenAI 账号及一个当前 ModelTrace GPT 模型发起检测
- **THEN** 探针使用该账号的凭据归属、协议及业务代理，直接发送选择的模型 ID，不得换用其他账号、映射目标或全局模型。

#### Scenario: OpenAI 模型列表

- **WHEN** 管理员打开全局 ModelTrace 设置或 OpenAI 账号的手动检测弹窗
- **THEN** 列表来自当前 ModelTrace GPT 模型，包含未被账号映射配置的模型，不包含 Claude 或其他非 OpenAI 家族模型。

#### Scenario: 不可调用模型

- **WHEN** 所选模型仍在 ModelTrace GPT 列表中，但账号凭据、协议或上游暂不支持该模型
- **THEN** 配置可以保存，检测实际尝试该模型并记录脱敏失败原因，不改用其他模型。

### Requirement: 次数与结论

手动和自动检测均支持 1–3 轮，默认 1。每轮发送独立挑战并收集完整回答；所选轮次全部有效后按 ModelTrace 逐回答评分聚合及样本数校准计算模型分布。结果包含归因第一名和概率，不另设概率门槛：第一名匹配实际所选目标模型即正常，否则降智。

多轮任务若有超时、鉴权或额度错误、限流、流中断、无效输出或评分失败，则记录失败、请求轮次和有效轮次，不自动补发隐藏重试，不产生新的账号正常/降智结论。HTTP 200、上游自报模型或票据长度不能替代内容评分。检测是概率性观测，不作为模型身份确定证明。

#### Scenario: 单轮与多轮评分

- **WHEN** 分别完成 1、2 或 3 轮有效挑战
- **THEN** 各自使用相应样本数校准，归因第一名等于实际所选模型则记录正常，否则记录降智；概率和指纹库版本可查询。

#### Scenario: 部分失败

- **WHEN** 请求 3 轮检测但仅 2 轮有效，或实际所选模型返回上游错误
- **THEN** 历史记录为失败并展示有效轮次和脱敏原因，不自动补发、不覆盖账号此前有效结论。

### Requirement: 手动检测弹窗

账号更多操作新增「检测降智」。点击打开统一弹窗的第一个页签「开始检测」，展示账号、来自当前 ModelTrace GPT 列表的模型选择和次数（默认 1），并提示会消耗该账号上游额度但不扣本站普通用户余额。确认开始前不发送探针。

任务创建后后端执行，弹窗显示排队/执行进度、已完成轮次、最终结论和错误。关闭弹窗不取消已创建任务，重新打开可读取在途任务和进度。同账号已有任务时显示该任务，避免重复创建。模型和次数的客户端与服务端校验一致。

#### Scenario: 关闭并重新打开

- **WHEN** 手动任务执行中关闭弹窗再重新打开
- **THEN** 任务继续运行，界面恢复其进度或结果，不因打开动作重复发起模型请求。

### Requirement: 全局自动设置

系统设置 → 网关设置保留「自动检测降智」区块：总开关、检测模型（单选）、检测轮次、默认检测间隔（分钟）。默认关闭、`gpt-6-astra`、1 轮、60 分钟；间隔允许 5–10080 分钟。参数及支持模型由服务器校验，启用时模型不得为空。

设置持久化并热更新，无需重启。改变默认模型或轮次只影响之后新建的、未配置账号覆盖的自动任务；已创建任务保存创建时模型快照。总开关关闭后不创建新自动任务，已执行任务允许完成，排队自动任务执行前重新检查资格。修改全局间隔只影响未设置账号级覆盖的自动任务。

#### Scenario: 热更新和关闭

- **WHEN** 管理员保存有效设置或关闭自动检测
- **THEN** 后续调度使用新配置，关闭后不再启动排队或新自动任务，手动检测仍可用；非法参数拒绝保存且不改变原配置。

### Requirement: 账号独立自动开关、模型与频率

OpenAI 账号创建/编辑界面提供「自动检测降智」独立开关、可选自动检测间隔和可选自动检测模型。新增账号默认关闭、模型覆盖为空；存量字段缺失或类型无效时按关闭或继承处理。模型覆盖为空时继承全局模型；非空值只允许当前 ModelTrace OpenAI GPT 列表中的模型。开关、模型和间隔保存后持久化。

自动资格同时要求全局开启、账号开关开启、账号启用且可调度、有效模型属于当前指纹列表。手动检测不受全局或账号自动开关限制，但仍校验账号存在、所选模型在 ModelTrace 列表中。账号当前没有所选模型映射不阻止保存或创建任务；探针直接发送所选模型，调用失败记录失败。

自动任务创建时保存账号有效模型快照。修改账号模型后，已排队任务在发送前发现快照与当前有效模型不一致则跳过并记录失败原因；已发送任务不强行取消，继续使用原模型完成并保留历史。不可调度账号跳过而不伪造降智记录，但仅因本账号 ModelTrace 降智隔离的账号仍须按有效间隔自动复检；因其他原因不可调用的账号不得仅凭 ModelTrace 特许复检。

#### Scenario: 开关和模型继承

- **WHEN** 全局开启但账号自动开关关闭，或账号未配置模型覆盖
- **THEN** 账号在前一种情况下不自动检测但仍可手动检测；在后一种情况下使用当前全局模型创建后续自动任务。

#### Scenario: 账号模型覆盖

- **WHEN** 全局模型为 `gpt-6-astra`，账号覆盖模型为 `gpt-6-sol`
- **THEN** 该账号后续自动任务使用 `gpt-6-sol`，不使用全局模型。

#### Scenario: 模型配置快照

- **WHEN** 账号模型覆盖在自动任务排队后、探针发送前发生变化
- **THEN** 旧排队任务不发送请求并记录配置变化原因；已发送任务使用创建时模型完成，历史保留其模型。

#### Scenario: 账号模型暂不可用

- **WHEN** 账号保存了合法 ModelTrace 模型但当前凭据、协议或上游不能调用它
- **THEN** 保存成功，自动或手动检测实际调用该模型并记录失败，不回退其他模型。

### Requirement: 降智时的账号级隔离策略

OpenAI 账号可独立配置是否在有效降智结论后进入临时不可调用状态，存量与新账号开关默认关闭。开启时，手动或自动检测任意所选模型得到有效降智结论，整个账号退出业务调度；后续手动或自动检测任意所选模型得到有效正常结论，解除仅由 ModelTrace 设置的隔离。账号隔离按最新一次有效结论变化，不按模型分别追踪；评分和历史仍记录具体模型。失败、超时、部分完成、配置变更导致的未发送任务不改变已有隔离。

关闭账号隔离策略时立即解除该策略造成的隔离，不清除其他原因的限流或临时不可调用；仅关闭全局或账号自动检测时，不解除既有 ModelTrace 隔离，但仍允许管理员手动检测。ModelTrace 对隔离的设置和解除不得覆盖其他原因的不可调用状态。

#### Scenario: 手动与自动降智

- **WHEN** 已开启隔离策略的账号完成手动或自动检测且有效结论为降智
- **THEN** 整个账号进入临时不可调用状态，其他模型也不被业务调度选中，检测历史记录所选模型。

#### Scenario: 隔离期间仍可自动复检

- **WHEN** 账号仅因 ModelTrace 降智处于临时不可调用状态且自动检测开关仍开启
- **THEN** 账号按其有效间隔继续接受使用有效账号模型的 ModelTrace 复检；有效正常结论可解除隔离，失败、超时或继续降智不得放开业务调度。

#### Scenario: 手动恢复与策略关闭

- **WHEN** 管理员手动检测得到有效正常结论，或关闭账号的降智隔离策略
- **THEN** 解除仅由 ModelTrace 造成的隔离；若存在其他独立原因，账号仍保持不可调用。

#### Scenario: 账号级最新有效结论

- **WHEN** 同账号模型 A 有效降智、随后模型 B 有效正常，接着发生一次失败检测
- **THEN** 模型 A 的降智先使账号隔离，模型 B 的正常解除隔离，最后失败不重新隔离；评分历史保留各次模型与结论。

### Requirement: 历史持久化与权限

同一弹窗的第二个页签「检测历史」按账号展示分页记录，按创建时间倒序，包含手动/自动来源、时间、选择模型和实际请求模型、请求/有效轮次、执行状态、最终结论、归因第一名/概率、耗时、失败原因及指纹库版本。保留 30 天，清理过期历史不抹掉单独保存的账号最新有效摘要。历史不保存 OAuth/API Key、代理密码、Cookie 或真实业务对话。

全部检测管理及历史接口仅管理员可访问，服务端检查账号 ID、分页和参数边界。账号删除后停止后续任务并清理对应历史/摘要，不能再通过旧 ID 获取结果。

#### Scenario: 来源和持久化

- **WHEN** 同账号先后执行手动与自动检测后刷新页面或重启服务
- **THEN** 30 天内的记录可分页查询并准确区分来源、所选模型、实际请求模型、轮次及结论；非管理员不能读取或触发检测。

### Requirement: 智商状态和历史入口

OpenAI 账号状态列增加第二行「智商：正常」或「智商：降智」，使用账号最近一次有效检测结果，不按模型汇总。没有有效结果显示「智商：未检测」。后续失败或未发送任务不覆盖既有有效结论；界面提供检测模型及时间，避免将旧结果误解为实时判断。

点击第二行直接打开统一弹窗的历史页签。检测开关关闭不删除历史或有效摘要，非 OpenAI 账号不增加智商行。前端遵循现有弹窗、表格、深色模式、键盘操作及中英文文案约定。

#### Scenario: 多模型最近结果

- **WHEN** 同账号 Astra 检测降智后 Sol 检测正常，再发生一次请求失败
- **THEN** 状态列显示最近有效的正常结果并标明 Sol 和检测时间，历史保留 Astra 降智及最新失败；点击状态进入该账号历史页签。

### Requirement: 作业安全与生命周期

手动/自动共享后台执行器，限制并发、单轮及总任务时长；通过持久化任务状态与互斥协调确保同账号不重叠，多实例下同一任务不被重复执行。正常退出停止新任务并处理在途取消，服务重启识别未完成任务为中断失败，不盲目重放可能已消耗额度的请求。旧任务不能覆盖较新的有效结论。

未启用隔离策略的检测不更改账号调度资格、优先级、状态、计费或打票策略；启用时只按本规格更改临时不可调用状态。结果与进度更新不得造成账号列表逐行查询数据库。

#### Scenario: 并发与中断

- **WHEN** 多实例或手动/自动同时请求检测同一账号，或执行中服务中断
- **THEN** 同账号最多一个任务执行，其他触发复用或等待既有任务；中断留下可查询的失败结果，不以正常/降智掩盖故障，也不自动重发已经发送的轮次。

## Verification and delivery boundary

覆盖 GPT-only 列表、账号模型继承与覆盖、直接调用所选模型、模型配置变更、手动/自动来源、失败与并发安全、既有降智隔离和历史行为。运行后端/前端定向测试、类型检查和构建，由独立只读 Verifier 验收。真实账号调用不是必需验收证据；如运行临时 PostgreSQL，测试结束必须关闭并确认测试端口关闭。
