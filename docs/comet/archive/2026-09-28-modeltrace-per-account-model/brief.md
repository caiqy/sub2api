# Outcome

为每个 OpenAI 账号增加独立的 ModelTrace 自动检测模型配置，并让手动检测使用按账号平台限定的 ModelTrace 模型列表。自动和手动检测都直接调用界面所选的模型 ID，避免被账号模型映射悄悄替换。

# Scope

- 全局 ModelTrace 设置继续提供默认检测模型；账号可选配置一个模型覆盖值，留空继承全局模型。
- OpenAI 账号创建、编辑页面提供账号级检测模型选择，选项来自 ModelTrace 当前支持的 GPT 模型列表。
- 手动检测弹窗使用同一来源的 OpenAI GPT 模型列表，不按账号模型映射或当前上游模型发现结果过滤。
- 服务端校验模型属于 ModelTrace 的 OpenAI GPT 列表；保存配置不要求账号当前已经有该模型映射或可调用能力。
- 自动任务创建和执行前读取有效账号模型；配置变更后尚未发送的旧排队任务跳过，已发出的任务完成并保留历史。
- 探针直接把所选模型 ID 发给该账号的实际上游；上游拒绝、凭据缺失或协议不支持按既有失败生命周期记录，不回退全局模型或其他模型。
- 非 OpenAI 账号不显示 ModelTrace 检测模型配置和检测入口。

# Non-goals

- 不新增非 OpenAI 平台的 ModelTrace 探针、认证协议、评分指纹或检测入口。
- 不把 ModelTrace 中用于评分对照的 Claude 等非 GPT 模型暴露到 OpenAI 检测列表。
- 不改变既有账号级检测间隔、降智隔离、历史保留、权限和任务并发语义。
- 不改变普通业务请求的模型映射规则；仅 ModelTrace 检测直连所选模型。

# Acceptance examples

### Scenario: 账号模型继承全局模型

- **WHEN** 账号未配置独立检测模型且全局模型为 `gpt-6-astra`
- **THEN** 后续自动任务使用 `gpt-6-astra`；修改全局模型只影响未配置账号的后续任务。

### Scenario: 账号模型覆盖全局模型

- **WHEN** 账号配置 `gpt-6-sol` 且全局模型为 `gpt-6-astra`
- **THEN** 后续自动任务使用 `gpt-6-sol`，不使用全局模型。

### Scenario: 模型配置快照与排队任务

- **WHEN** 账号模型配置在任务排队后、探针发送前发生变化
- **THEN** 旧排队任务不发送请求并记录失败或跳过原因；已发送任务不被强行取消，完成后保留原模型历史。

### Scenario: 手动模型列表按平台限定

- **WHEN** 管理员打开 OpenAI 账号的手动检测弹窗或全局 ModelTrace 设置
- **THEN** 列表来自 ModelTrace 当前 GPT 模型，包含未被该账号映射配置的模型，但不包含 Claude 等非 OpenAI 模型。

### Scenario: 直接调用所选模型

- **WHEN** 管理员或自动任务选择 `gpt-6-sol` 发起检测
- **THEN** 探针使用所选账号的凭据、协议、代理，并将 `gpt-6-sol` 作为实际上游模型 ID；不得改用账号映射目标、全局模型或其他账号。

### Scenario: 所选模型暂不可调用

- **WHEN** 配置模型仍属于 ModelTrace 列表，但账号凭据、协议或上游不支持该模型
- **THEN** 配置仍可保存；检测实际尝试所选模型，失败时记录脱敏失败原因，不静默换用其他模型。

# Constraints and invariants

- ModelTrace 模型列表以服务端当前指纹库为准，服务端是校验权威。
- 当前指纹库中仅向 OpenAI 检测列表暴露 GPT 家族模型；评分库中的其他家族不进入该列表。
- 手动和自动检测都使用账号实际凭据归属和业务代理；记录选择模型及实际模型，不切换账号。
- 自动模型有效值为账号覆盖或全局默认；空覆盖表示继承，不保存伪造运行态字段。
- 失败、超时和配置变更造成的未发送任务不能覆盖最近一次有效结论或改变降智隔离状态。
- 临时 PostgreSQL 集成测试结束后必须停止测试实例并确认测试端口关闭，不得停止用户原本运行的数据库。

# Decisions

- D1：每个账号最多配置一个自动检测模型；未配置时继承全局模型。
- D2：手动模型列表不按账号模型映射过滤，但按账号平台限定；本 change 仅支持 OpenAI。
- D3：保存时只校验模型属于 ModelTrace 的 OpenAI GPT 列表，允许账号暂时没有该模型能力。
- D4：检测时直接调用所选模型 ID；账号映射不参与 ModelTrace 探针目标解析。
- D5：所选模型不可调用时明确失败，不回退到全局模型或其他模型。
- D6：配置变更后，排队任务在发送前重新校验有效模型；已发送任务完成并保留创建时模型历史。

# Verification expectations

- 后端单元测试覆盖模型列表 GPT-only、全局继承、账号覆盖、模型变更前置校验、直接调用和失败不回退。
- 前端测试覆盖创建/编辑账号的模型选择、清除覆盖继承全局、手动弹窗模型列表及非 OpenAI 隐藏。
- 运行相关 Go 测试、前端测试、类型检查、构建和 `git diff --check`。
- 如运行 PostgreSQL 集成测试，测试结束关闭并确认测试端口不再监听。
- 由独立只读 Verifier 对全部验收项验收；不执行真实上游账号调用，除非另行明确授权。
