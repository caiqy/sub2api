# Outcome

集成 ModelTrace，在管理员账号管理中提供手动及自动降智检测、持久化历史和可点击的账号智商状态。覆盖全部 OpenAI 账号，评分成功后按归因第一名直接判定，账号显示最近一次有效检测结果。账号独立开关仅控制自动检测，默认关闭。当前整理为最终 Shape 确认稿，按用户要求在 Build 前暂停，等待用户压缩上下文后明确通知继续。

# Scope

用户原始请求：
> 我想为本项目集成modeltrace实现定时检测降智的功能，也支持在账号的更多操作里面执行手动检测降智功能，点击后弹窗显示降智检测界面，选择检测模型和检测次数（默认1次）后确认开始，弹窗中第二个tab为检测历史，包含手动和自动 系统设置-》网关设置中增加 自动检测降智的开关、检测模型、检测轮次、检测间隔 账号管理界面，状态列增加第二行：智商：正常/降智，点击后弹出检测历史（复用上面的弹窗）

- 本地运行 ModelTrace 挑战生成、输出指纹提取与归因，保留上游许可证、来源版本和对应校准参数。
- 账号更多操作新增「检测降智」；同一弹窗提供「开始检测」「检测历史」两个页签。手动选择检测模型、次数，次数默认 1。
- 系统设置 → 网关设置增加自动检测开关、检测模型、检测轮次、检测间隔。
- 手动和自动检测共用执行、结果计算与历史存储；历史区分来源。
- 账号状态列第二行显示「智商：正常/降智」，点击打开同一弹窗的历史页签；没有有效结论时显示「智商：未检测」，失败不覆盖历史有效结论。
- 仅管理员可操作或查看；非支持类型的账号不发送探针。
- 用户追加要求：为每个账号增加独立开关，默认关闭。

# Non-goals

- 不恢复或改造旧打票功能，不把检测结果自动用于换号、停用、调度降权或计费调整。
- 不将 ModelTrace 概率当作上游模型身份的确定性证明，不以响应 model 字段或票据长度替代内容归因。
- 不引入外部检测服务，不向第三方发送账号凭据。

# Acceptance examples

- A1：从账号更多操作打开检测弹窗，选择支持的模型及次数（初始为 1），确认后看到进度和结果。
- A2：手动与自动检测记录均出现在第二个历史页签，记录账号、触发来源、时间、模型、轮次、结果、归因概率、耗时及失败原因，刷新页面后仍可查询。
- A3：网关设置保存自动检测配置后无需重启；关闭时不再创建自动检测，手动检测仍可运行。
- A4：账号状态第二行展示检测结论，点击直接打开该账号历史页签。
- A5：网络、认证、限流、无效输出等错误记录为检测失败，不伪装为正常或降智。
- A6：轮次为 1 时可以正常评分；多轮按有效输出对应的校准参数聚合，并显示请求轮次与有效轮次。
- A7：并发手动与自动任务不会重复测试同一个账号；账号凭据、代理密码及 Cookie 不进入历史或接口。
- A8：每个账号有可持久化的独立自动检测开关，新增及存量缺失配置均视为关闭；关闭账号不被自动检测，但仍可手动检测。

# Constraints and invariants

- 手动次数默认 1 是用户已明确要求；最终确认稿采用 1–3 轮，对应已调研的校准档位。每轮独立发送一道挑战，全部所选轮次有效后聚合评分；不自动补发隐藏重试。未完成全部轮次时记录失败及实际有效轮次，不更新账号结论。
- 检测请求消耗被测账号的上游额度，应在开始检测页说明；不扣本站普通用户余额。
- 检测绑定目标账号及其实际业务代理，不通过账号池自动换号凑样本。
- 现有账号测试包含模型映射、OAuth/API Key 及多平台分支；比较对象为按账号配置解析后的有效上游模型，历史同时保留用户选择与实际目标。映射目标不在指纹库时拒绝开始并说明原因，不能通过回显 model 字段伪造正常。
- 历史查询必须分页；后台执行有并发上限、超时和停止管理；多实例须防止重复执行同一任务。
- 指纹库使用可追溯固定版本，界面和结果保留来源版本；首版不自动更新指纹库。
- 最终确认稿的自动配置默认值：关闭、单选 gpt-6-astra、1 轮、间隔 60 分钟；自动只扫描独立检测开关已开启、启用且可调度的 OpenAI 账号。间隔按分钟配置，服务端限制为 5–10080 分钟。
- 历史保留 30 天并分页查询；账号最新有效结论独立保留并标明检测时间。关闭弹窗后已创建的后台任务继续运行，重新打开能看到进度。
- 账号独立开关放在 OpenAI 账号创建/编辑界面，明确标注「自动检测降智」。账号列表的智商状态链接不承担开关职责。
- 全局或账号开关关闭后停止为其创建新自动任务；正在执行的任务允许完成并写历史。已有排队自动任务执行前重新检查开关和账号资格。
- 初次启用账号自动检测后在下一次后台扫描创建首个任务；后续按该账号上次自动任务结束时间及全局间隔调度，手动任务不改变自动周期。
- 账号删除后不再检测或保留其可访问历史；服务重启中断的在途检测明确记为中断失败，不自动重放已发送请求。

# Decisions

- 已由 `/comet` 解析到 Native；change 为 `modeltrace-degradation-detection`。
- 创建时工作树干净且没有其他活跃 change，按 Runtime 默认使用当前 main 工作区。
- 已定位可复用入口：AccountsView、AccountActionMenu、AccountStatusIndicator、AccountTestModal、ScheduledTestService/Runner、SettingService 与 SettingsView。
- 现有定时测试是连通性测试，不能把它的成功/失败直接当作 ModelTrace 归因结果。
- 所有改动属于同一条检测流程，共享执行器、历史和界面契约，暂按单个 change 管理，不建立 Supervisor 子任务。
- 上轮调研材料仅作实现参考，不将任何衍生项目的未经验证宣传或测试准确率当作本功能验收标准。
- Q1 已确认：覆盖 OpenAI 全部账号，包含 OAuth 订阅与 API Key；使用各账号支持的实际请求协议，其他平台不提供检测入口。
- Q2 已确认：不设置概率门槛；评分成功时归因第一名匹配目标模型为正常，否则为降智。未测过为未检测；请求错误或样本不足记失败，不覆盖已有有效结论。
- Q3 已确认：账号状态使用最近一次有效检测结果，不按各模型聚合；其他模型旧结果保留在历史。
- 用户追加决定：每个账号独立开关默认关闭，全局开启不能绕过账号关闭状态执行自动检测。
- Q4 已确认：账号独立开关仅控制自动检测；全局或账号自动开关关闭均不影响手动检测。
- 用户指定暂停边界：Build 正式开始前停止，等待用户压缩上下文并明确要求继续。需求确认与继续执行是两个条件，单独确认需求不解除暂停。

- 执行受影响 Go/Vue 测试、类型检查、构建和必要生成检查，再由独立只读 Verifier 验收。
