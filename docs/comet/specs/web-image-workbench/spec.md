# Web AI 生图工作台

## Purpose

为 Sub2API 已登录用户提供通过平台 API Key 使用 GPT Image 的生成、参考图编辑、结果查看和历史复用流程。工作台依托既有同步 Images 网关和用量历史；列表应以有界摘要呈现，完整图片只在查看结果或历史详情时读取。

## Requirement: 工作台布局与品牌

系统 SHALL 在现有 `/images` 路由和 AppLayout 中提供左侧创作输入、右侧图片预览的桌面布局，在窄屏切换为纵向布局。提示词和参考图属于主要输入，尺寸与质量等常用选项紧凑排列，高级参数折叠。历史区域按需展开。继续使用项目的 Vue、Tailwind、系统中文字体和青色主题，不增加字体或组件依赖。

设计令牌复用项目：画布 gray-50 `#f9fafb`、面板白色 `#ffffff`、正文 gray-900 `#111827`、主操作 primary-700 `#0f766e`、暗色面板 dark-800 `#1e293b`、暗色画布 dark-950 `#020617`。小字主按钮选足够对比度的深青色；表单 12px、工作区 16px 圆角，避免多重嵌套装饰卡片。图片预览是页面视觉主角；动效只用于展开、状态更新和点击反馈，尊重 reduced-motion。

```text
┌──────────────────────────────────────────────────────────┐
│ AI 生图                         平台 API Key               │
├─────────────────────┬────────────────────────────────────┤
│ 生成 / 编辑         │ 图片预览                            │
│ 提示词              │ 等待状态 / 渐进预览 / 最终结果      │
│ 参考图（编辑时）    │                                    │
│ 模型 / 尺寸 / 质量  │ 预览 · 下载 · 送入编辑              │
│ 高级参数            │                                    │
│ 生成图片 / 停止等待 │ 历史记录（展开后分页与筛选）        │
└─────────────────────┴────────────────────────────────────┘
```

### Scenario: 桌面与窄屏使用

验收：A1

- WHEN 用户在桌面或手机宽度打开工作台，切换生成/编辑或展开高级参数/历史。
- THEN 创作与图片区域适配对应布局，无页面横向溢出；可通过键盘操作，控件有标签和可见焦点，明暗主题及预览对话框焦点行为可用。

## Requirement: 平台 Key 与模型发现

系统 SHALL 使用用户现有平台 API Key 调用网关。Key 列表的分页应可达，不把第一页 100 个记录当作全部 Key。模型候选通过所选 Key 的 `/v1/models` 配置可见性发现；已知 GPT Image 模型（包括本网关已支持的 2.5 系列及快照）按适用参数提供操作。别名或未知兼容项使用保守参数；不因官方模型目录存在而宣称当前 Key 有实际远程资格。

模型发现失败与空候选区别显示；重试仅重试模型读取。切换 Key 后旧请求不得覆盖新候选。不将平台 Key 写入上游配置或额外浏览器持久化，不向浏览器泄露上游账号凭据。

### Scenario: 切换 Key 与发现异常

验收：A2

- WHEN 用户翻页选择 Key、快速切换 Key，或模型发现返回失败/空列表。
- THEN 可读取当前 Key 候选并明确呈现状态，旧响应被忽略；失败允许明确重试，未生成图片验证资格。

## Requirement: 模型参数

系统 SHALL 保留一次请求一张图片的默认。画面比例默认“自动”，对应 size=auto，并保留方形、横向、纵向和已有自定义尺寸；自动由模型决定输出尺寸，不保证与参考图同尺寸或同比例。尺寸、质量、背景、输出格式和 moderation 按已知模型能力校验；2.5 的 xhigh/max 不得发送给旧模型。保留已有自定义尺寸的像素/宽高比/16 倍数校验。透明背景只使用 PNG/WebP；JPEG/WebP 才发送压缩参数。GPT Image 不新增旧 style 或 response_format:url 参数。历史回放先填写表单，再按当前模型重新验证，禁止自动提交。

### Scenario: 模型切换与参数复用

验收：A3

- WHEN 用户切换新旧模型、选择透明 JPEG、输入非法尺寸或复用历史参数。
- THEN 表单拒绝或修正不兼容组合并告知原因，请求不包含该模型不支持的新选项，默认 n=1。

## Requirement: 同步渐进生成

系统 SHALL 保留 `/v1/images/generations` 和 `/v1/images/edits` 路由，使用 fetch POST 携带平台 Key 与 JSON/FormData 请求。根据响应 Content-Type 支持标准 Images SSE 和普通 JSON，处理 `image_generation.partial_image`、`image_edit.partial_image`、两类 `completed` 与错误事件/信封。

流解析应支持 UTF-8 跨字节分块、CRLF、多行 data、注释心跳和可选 `[DONE]`，不得假设每次 reader.read 就是完整事件或每条路径必有 `[DONE]`。partial 是草稿，只更新预览；成功必须有最终图片。最终图仍读取至正确结束，使用已完成结果去重，不因缺少请求的 partial 数量报错。elapsed 时间来自当前请求，不通过提示词模糊匹配历史计算。

### Scenario: SSE 和 JSON 成功

验收：A4

- WHEN 生成或编辑返回 partial、最终图片、普通 JSON，或正常流没有 `[DONE]`。
- THEN 草稿及时显示、最终图正确显示且计成功，分块/心跳不会破坏协议解析。

## Requirement: 失败、停止等待与重复费用

系统 SHALL 在仅 partial 后 EOF、协议错误、显式错误、HTTP 错误或客户端停止等待时显示准确状态。停止等待只停止浏览器读取，不表示远程取消、退款或免费；当前网关可能继续 drain 上游并计费。失败保留提示词/参数/参考图和已有最终结果，不自动重新提交生图。新的请求使用独立取消及竞态标识，旧请求不覆盖新状态，离开页面释放 timer、reader 和临时 Blob URL。

### Scenario: 未完成断流和停止等待

验收：A5

- WHEN 只有草稿的流结束、收到错误，或用户点击停止等待后再次生成。
- THEN 不把草稿计成功，不丢已完成图片，不自动重试；停止等待提示可能继续生成与计费，旧回调不改写新请求。

## Requirement: 多参考图与上传蒙版

系统 SHALL 在编辑时支持选择/移除最多 16 张 PNG/JPEG/WebP 参考图，每张不超过当前网关 20 MiB part 限制并可解码。客户端核对真实格式与声明 MIME；服务端继续执行现有总 body 和解析限制。FormData 使用后端已有多图字段约定，蒙版作用于第一张图。

蒙版 SHALL 是小于 4,000,000 字节、带 alpha 的 PNG，与第一张参考图像素尺寸相同。改变第一图时重新校验蒙版。入口使用“原始 / 参考图片”和“局部修改范围（可选）”，分别说明“上传你想修改的图片”和“上传蒙版，指定主要修改哪里；留空则根据描述编辑”。说明蒙版的透明区域为希望修改的区域，其余不透明区域希望保留；多图时作用于第一张。蒙版提供提示引导，不承诺严格局部像素保护。本 change 不加入画布涂抹工具或源图持久化。

### Scenario: 编辑输入验证

验收：A6

- WHEN 用户添加多个参考图、非法/过大图片、过多参考图或不符合要求的蒙版。
- THEN 合法多图进入现有编辑接口，不合法输入被阻止并指出原因，蒙版始终校验第一参考图。

## Requirement: 结果复用、预览与下载

系统 SHALL 对当前与可用历史结果提供预览、下载和送入编辑。根据最终 output_format、dataURL 或有效 MIME 使用正确扩展名，不把 JPEG/WebP 标为 PNG。送入编辑把图片转换为可用参考文件、保留合理参数并切换模式，不自动提交。外部 URL 保留既有安全 URL 检查；跨域不能读取、下载失败或签名失效时给出操作指引，不为此增加任意 URL 服务端代理。

### Scenario: 结果成为编辑参考图

验收：A7

- WHEN 用户预览/下载或将当前/历史的可用结果送入编辑。
- THEN 对应结果可用且下载格式正确，送入编辑只填表；URL 读取失败或失效明确显示，并可以重新上传下载后的图片。

## Requirement: 历史分页与按需读取

系统 SHALL 支持默认 20 条分页、总数、API Key、生成/编辑和状态筛选；筛选变化回到第一页。打开历史区域才加载文字摘要列表，点击记录才加载详情，不预取每条完整图片。详情图库使用原生 loading=lazy/decoding=async 和稳定尺寸，避免无谓的离屏解码。复用最近已加载状态、同一在途请求，并防止筛选/分页/详情选择竞态；不要为 n=20 的分页列表引入新虚拟化依赖。

### Scenario: 打开、筛选与翻页历史

验收：A8

- WHEN 首次打开工作台、展开历史、快速筛选/翻页或选择详情。
- THEN 工作台首屏不请求历史详情，筛选与页码正确、旧响应不覆盖新页；耗时显示不触发历史匹配查询。

## Requirement: 历史列表有界投影

系统 SHALL 从已按用户、图片端点和筛选授权的本页用量记录取得 ID，页内一次批量读取请求摘要，并只 hydrate 列表所需 API Key 关联。非空页列表仓储不超过 5 次数据库查询：count、详情表存在检查、分页记录、API Key 关联、请求摘要查询；空页跳过无用 batch。不得为每条记录调用完整详情，也不得 SELECT response_body/upstream_response_body。

批量投影 SHALL 只选择既有优先级下的有效请求正文及相应头：优先真实非空 RequestBody，仅其真实为空时才采用上游正文；正文大于 256 KiB 或头大于 8 KiB 时不把其全量传入 Go。超界非空正文不误当空值读取另一个大正文。旧大型 JSON dataURL/multipart 请求列表显示摘要不可用，可点击原有详情路径；缺失详情仍保留用量列表记录。列表 prompt 最多 256 个 Unicode 字符，不截断详情完整 prompt。兼容 TEXT 中的原始 JSON、multipart、omitted marker 和截断内容，不盲目 cast jsonb，也不引入 PostgreSQL 16+ 专属 guard。

### Scenario: 大请求与大响应历史页

验收：A9

- WHEN 读取 20 或 50 条页，包含大 base64 响应、dataURL 源图和旧原始 multipart。
- THEN 查询数不随条数变成 2N，正文/头投影受上限约束，HTTP 列表没有图片正文；超界旧请求列表明确降级，单条详情仍可按原路径读取。

## Requirement: 请求摘要正确解析

系统 SHALL 复用现有 request_body_preview parser 解封生产快照，再共享解析 JSON 或有界 multipart。新编辑摘要保留 prompt、模型参数和 had_source_image/had_mask 指示，不写入原始文件/dataURL。修复新 multipart 摘要主动清空 prompt 的行为；已丢失的旧 prompt 显示未保留，不用 revised_prompt 冒充用户原始 prompt。

### Scenario: 生产编辑摘要与旧记录

验收：A10

- WHEN 列表或详情读取 preview envelope、新 multipart 摘要、旧空摘要、原始 JSON/multipart 或不完整内容。
- THEN 能保留的提示词/参数正确显示，新 multipart 不再丢 prompt；丢失/超界内容不伪造，不使整页失败。

## Requirement: 现有历史结果与保留状态

系统 SHALL 在现有日志详情保留范围内解析 JSON base64、URL 和 SSE 最终图片，partial 不作为成功图片。详情不存在或已清理时保留列表账单元信息并展示不能恢复图片的明确状态；远程 URL 失效与无图片结果分别处理。历史编辑参数回放仍要求重新上传原参考图和蒙版，而可用输出可以送入新编辑。保留策略遵循管理员配置，说明其全站共享性质，不将默认 300 条写成每用户或永久图库保证。

### Scenario: 流式历史和已清理详情

验收：A11

- WHEN 查看 JSON/SSE/URL 历史、已清理详情或失效链接，并复用编辑记录。
- THEN 可用最终图片能预览复用，草稿不冒充最终图片；不可用状态明确，原始编辑输入需重新上传。

## Requirement: 权限、兼容与验证

系统 SHALL 保持历史用户所有权、Key 筛选权限及网关鉴权、调度、审核、配额和计费。批量 ID 来自服务端授权页，不接受未授权客户端 ID 集合。所有任务改动限定 DSH 指定隔离目录，保留既有路由、PostgreSQL 14+ 与技术依赖。

通过定向 mock 验证 SSE 分块与异常、表单和列表请求竞态；通过仓储夹具验证查询数和大字段投影；完成类型检查及生产构建，由独立只读 Verifier 核对完整验收。真实上游生图没有运行时不得宣称模型/OAuth 资格实测成功。不得自动执行付费探测、部署、提交/合并/推送/清理；最终通过 DSH 验收条交付。

### Scenario: 权限和交付验证

验收：A12

- WHEN 同用户/跨用户请求历史，以及对当前候选运行检查和独立验收。
- THEN 已有权限边界保持，查询检查及回归有真实证据；未执行真实付费验证如实记录，所有正式交付写入当前隔离目录。
