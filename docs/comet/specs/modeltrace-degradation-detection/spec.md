# ModelTrace 降智检测规格

## Purpose

为全部 OpenAI 账号提供 ModelTrace 内容归因检测、定时与手动触发、检测历史和账号智商状态。检测只提供观测结果，不控制账号业务调度或恢复旧打票功能。

## Requirements

### Requirement: 支持范围与本地归因

支持 OpenAI 平台全部账号，包含 OAuth 订阅、API Key 及现有 OpenAI 认证变体；按现有凭据解析和协议配置使用 Responses 或 Chat Completions 路径。凭据影子账号复用现有凭据归属解析，检测记录仍归属于用户选择的账号。非 OpenAI 平台不展示检测操作。

内嵌可追溯固定版本的 ModelTrace 挑战生成逻辑、评分核心与指纹库，保留许可证、版权及来源 commit。评分在服务器本地运行，首版不自动更新指纹库。模型选择只提供指纹库支持且账号配置允许的 GPT 文本模型。

探针使用所选账号的实际业务出口和身份配置，不使用打票代理或通过账号池换号。模型映射存在时同时记录选择模型与解析后的有效上游目标，按有效目标归因比较；不在指纹库的映射目标须在发送前拒绝并说明原因。

#### Scenario: 账号和模型隔离

- **WHEN** 管理员选择某 OpenAI 账号及一个支持的模型发起检测
- **THEN** 探针使用该账号的凭据归属、协议及业务代理，记录选择模型与有效目标模型；不得换用其他账号并将其结果归入所选账号。

### Requirement: 次数与结论

手动和自动检测均支持 1–3 轮，默认 1。每轮发送独立挑战并收集完整回答；所选轮次全部有效后按 ModelTrace 的逐回答评分聚合及对应样本数校准计算模型分布。结果包含归因第一名和概率，不另设概率门槛：第一名匹配有效目标模型即正常，否则降智。

单轮即可形成有效结论。多轮任务若有超时、鉴权或额度错误、限流、流中断、无效输出或评分失败，则记录失败、请求轮次和有效轮次，不自动补发隐藏重试，不产生新的账号正常/降智结论。HTTP 200、上游自报模型或票据长度均不能替代内容评分。检测是概率性观测，不作为模型身份的确定证明。

#### Scenario: 单轮与多轮评分

- **WHEN** 分别完成 1、2 或 3 轮有效挑战
- **THEN** 各自使用相应样本数校准，归因第一名等于有效目标则记录正常，否则记录降智；概率和指纹库版本可查询。

#### Scenario: 部分失败

- **WHEN** 请求 3 轮检测但仅 2 轮有效，或上游返回错误
- **THEN** 历史记录为失败并展示有效轮次和脱敏原因，不自动补发、不覆盖账号此前有效结论。

### Requirement: 手动检测弹窗

账号更多操作新增「检测降智」。点击打开统一弹窗的第一个页签「开始检测」，展示账号、模型选择、次数（默认 1），并提示会消耗该账号上游额度但不扣本站普通用户余额。确认开始前不发送探针。

任务创建后后端执行，弹窗显示排队/执行进度、已完成轮次、最终结论和错误。关闭弹窗不取消已创建任务，重新打开可读取在途任务和进度。同账号已有任务时显示该任务，避免重复创建。模型/次数的客户端与服务端校验一致。

#### Scenario: 关闭并重新打开

- **WHEN** 手动任务执行中关闭弹窗再重新打开
- **THEN** 任务继续运行，界面恢复其进度或结果，不因打开动作重复发起模型请求。

### Requirement: 全局自动设置

系统设置 → 网关设置增加「自动检测降智」区块：总开关、检测模型（单选）、检测轮次、检测间隔（分钟）。默认关闭、gpt-6-astra、1 轮、60 分钟；间隔允许 5–10080 分钟。参数及支持模型由服务器校验，启用时模型不得为空。

设置持久化并热更新，无需重启。改变默认模型或轮次只影响后续新任务，已创建任务使用创建时配置快照。总开关关闭后不创建新自动任务，已执行任务允许完成，排队自动任务执行前重新检查资格。

#### Scenario: 热更新和关闭

- **WHEN** 管理员保存有效设置或关闭自动检测
- **THEN** 后续调度使用新配置，关闭后不再启动排队或新自动任务，手动检测仍然可用；非法参数拒绝保存且不改变原配置。

### Requirement: 账号独立自动开关

OpenAI 账号创建/编辑界面增加「自动检测降智」独立开关。新增账号默认关闭，存量配置缺失或非布尔真值也视为关闭，开关保存后持久化。自动资格同时要求全局开启、账号开关开启、账号启用且可调度、目标模型支持。手动检测不受全局或账号自动开关限制，但仍校验账号存在、凭据与模型支持。

初次启用且符合条件的账号在下一后台扫描开始首个任务；后续按该账号上次自动任务结束时间及全局间隔调度。手动任务不改变自动周期。不可调度账号跳过而不伪造降智记录；队列执行前重新校验。

#### Scenario: 开关组合

- **WHEN** 全局开启但账号独立开关关闭，或全局关闭而账号开关开启
- **THEN** 该账号不被自动检测，但管理员仍可发起手动检测；只有两个开关均开启且账号符合资格时才自动检测。

### Requirement: 历史持久化与权限

同一弹窗的第二个页签「检测历史」按账号展示分页记录，按创建时间倒序，包含手动/自动来源、时间、选择模型和有效目标、请求/有效轮次、执行状态、最终结论、归因第一名/概率、耗时、失败原因及指纹库版本。保留 30 天，清理过期历史不抹掉单独保存的账号最新有效摘要。历史不保存 OAuth/API Key、代理密码、Cookie 或真实业务对话；保存诊断元数据和各轮评分信息即可。

全部检测管理及历史接口仅管理员可访问，服务端检查账号 ID、分页和参数边界。账号删除后停止后续任务并清理对应历史/摘要，不能再通过旧 ID 获取结果。

#### Scenario: 来源和持久化

- **WHEN** 同账号先后执行手动与自动检测后刷新页面或重启服务
- **THEN** 30 天内的记录可分页查询并准确区分来源、模型、轮次及结论；非管理员不能读取或触发检测。

### Requirement: 智商状态和历史入口

OpenAI 账号状态列增加第二行「智商：正常」或「智商：降智」，使用该账号最近一次有效检测结果，不按模型汇总。没有有效结果显示「智商：未检测」。后续失败不覆盖既有有效结论；界面提供检测模型及时间，避免将旧结果误解为实时判断。

点击第二行直接打开统一弹窗的历史页签。检测开关关闭不删除历史或有效摘要，非 OpenAI 账号不增加智商行。前端遵循现有弹窗、表格、深色模式、键盘操作及中英文文案约定。

#### Scenario: 多模型最近结果

- **WHEN** 同账号 Astra 检测降智后 Sol 检测正常，再发生一次请求失败
- **THEN** 状态列显示最近有效的正常结果并标明 Sol 和检测时间，历史保留 Astra 降智及最新失败；点击状态进入该账号历史页签。

### Requirement: 作业安全与生命周期

手动/自动共享后台执行器，限制并发、单轮及总任务时长；通过持久化任务状态与互斥协调确保同账号不重叠，在多实例下同一任务不被重复执行。正常退出停止新任务并处理在途取消，服务重启识别未完成任务为中断失败，不盲目重放可能已消耗额度的请求。旧任务不能覆盖较新的有效结论。

检测不自动更改账号调度资格、优先级、状态、计费或打票策略。结果与进度更新不得造成账号列表逐行查询数据库。

#### Scenario: 并发与中断

- **WHEN** 多实例或手动/自动同时请求检测同一账号，或执行中服务中断
- **THEN** 同账号最多一个任务执行，其他触发复用或等待既有任务；中断留下可查询的失败结果，不以正常/降智掩盖故障，也不自动重发已经发送的轮次。

## 验证与交付边界

使用上游固定样本交叉验证本地算法，覆盖单轮、多轮、无效输出、失败不覆盖、开关组合、权限、历史分页/保留、任务重入和重启中断。运行相关后端/前端测试、类型检查及构建，由独立只读 Verifier 验收；是否完成真实账号测试必须如实记录。

本 change 按单项需求维护，共享执行、历史与界面契约，不拆分 Supervisor。用户要求在 Build 前暂停：只有用户确认完整 Shape 且在压缩上下文后明确要求继续，才能执行进入 Build 的确认命令。
